# Phase 2 implementation plan

> **For agentic workers:** Use superpowers:executing-plans and test-driven development. Implement only Phase 2.

**Goal:** Classify every scheduled 2023–2025 Grand Prix and save the combined clean-lap dataset, audit, manifest and summary figure.

**Spec:** CLAUDE.md, PRD.md, IMPLEMENTATION_GUIDE.md §§5 and 10 Phase 2, and the user's explicit task.

**Architecture:** Extend the verified free archive adapter with a packaged immutable source catalog. Put inclusion decisions in manifest.py and dataset assembly in dataset.py; scripts orchestrate exports and measured log entries. Keep features and modelling untouched.

## Constraints and decisions

- Windows/PowerShell, single-line commands, existing dependencies only, paths from config, no notebooks.
- User explicitly authorizes TRAIN_YEARS + TEST_YEARS ingestion in Phase 2. The 2025 exception is limited to fixed data preparation and requested quality counts; no tuning, feature construction or prediction evaluation.
- Keep the Phase 1 source and original API compatible. Add a separate catalogued archive loader for the three configured seasons; retain source corrections/precision disclosures.
- Cache original JSON and provenance. Pin source commits, source hashes and schedule metadata for all 70 races. No telemetry or OpenF1 endpoints.
- Exclude if load fails, wet-compound share >0.05, or any rainfall. When both wet reasons apply, primary reason is wet_compound; retain both measurements for review.
- Unknown/missing weather cannot imply dry: treat unverifiable inputs as load_error.
- Preserve existing manual_override and optional manual_note. Include overrides require a successful load; forced exclusions of otherwise dry races use the explicit additional reason manual_override. Preserve automatic decision fields so overrides remain auditable.
- Review flags are data-quality diagnostics, not new inclusion thresholds: load errors; wet-tyre/rainfall disagreement; sparse wet-tyre use; unknown compounds; red-flag sessions; absent roster drivers; zero/low clean retention; and missing matched weather.
- Dataset build preserves lap/stint identity, labels split from fixed season config, and joins only past weather after cleaning. Per-race failures are logged and collected; an incomplete included-race build must exit nonzero rather than claim full success.
